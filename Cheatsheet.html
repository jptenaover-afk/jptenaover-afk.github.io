⚡ Blocking vs Non-Blocking — La pregunta más repetida del examen EXAMEN x3

=  BLOCKING
  • Se ejecuta inmediatamente, en orden secuencial
  • El resultado está disponible en la siguiente línea
  • Usar en bloques combinacionales
  • Simula bien la lógica combinacional
a = b + c;   // a ya tiene el nuevo valor
d = a & e;   // usa el nuevo a
<=  NON-BLOCKING
  • 1º Evalúa todos los RHS (capturas simultáneas)
  • 2º Asigna todos los LHS (al final del timestep)
  • Usar en bloques secuenciales (flip-flops)
  • Elimina condiciones de carrera
d2 <= d1;  // Lee d1 (valor ANTIGUO)
d3 <= d2;  // Lee d2 (valor ANTIGUO)
// Resultado: registro desplazamiento ✓
✓ CORRECTO — secuencial con <=
always @(posedge clk)
  d2 <= d1; d3 <= d2;  // shift register ✓
✗ MAL — secuencial con =
always @(posedge clk)
  d2 = d1; d3 = d2;  // resultado impredecible ✗
⚠️ Trampa clásica de examen: mezclar blocking y non-blocking en el mismo bloque secuencial. El comportamiento es impredecible en síntesis, aunque en simulación pueda dar resultado aparente. La pregunta de los registros en cadena (d1→d2→d3) con = es resultado impredecible; con <= es shift register predecible.

🔌 Tipos de datos: wire vs reg EXAMEN

TipoAsignación en...Representa
wire assign o salida de submódulo Cable de conexión, no almacena
reg Dentro de always o initial Variable con capacidad de almacenar
Reglas de los puertos
  • Las inputs son siempre wire (implícito)
  • Las outputs pueden ser wire o reg
  • Una salida de submódulo instanciado → conectar a wire
  • Un reg puede generar lógica combinacional o secuencial dependiendo del bloque
Regla de oro
// ¿Dónde le asigno valor?
assign f = a & b;    // → f debe ser wire
always @(...)        // → variable debe ser reg
  f = a & b;
submod u1(.q(f));    // → f debe ser wire
⚠️ No puedes asignar dentro de initial/always a un wire. Error frecuente de examen.

⏱️ Procesos: initial vs always EXAMEN

initial
  • Se ejecuta una sola vez (t=0)
  • No sintetizable
  • Solo para testbenches
  • Asignaciones sobre reg
  • Varios initial se ejecutan en paralelo
always
  • Se repite indefinidamente (bucle)
  • Sintetizable
  • Diseño RTL
  • Asignaciones sobre reg
  • Varios always se ejecutan en paralelo
Controles temporales
#10          // espera 10 unidades de tiempo
@(posedge clk)  // espera flanco de subida
@(a or b or c)  // espera cambio en a, b o c
wait(expr)      // espera hasta que expr sea true
fork / join (paralelo)
// begin/end → secuencial (retardos acumulados)
// fork/join → paralelo (retardos desde el inicio)
initial fork
  #5  B = 1;   // ocurre en t=5
  #10 C = 0;   // ocurre en t=10 (no t=15)
join

📋 Lista de sensibilidad & RTL synthesis

✓ Combinacional
always @(a or b or sel)
// ó en Verilog 2001:
always @(*)
// Asignaciones: =  (blocking)
// Lista: TODAS las entradas
✓ Secuencial (FF)
always @(posedge clk)
// con reset asíncrono:
always @(posedge clk or
         negedge rst_n)
// Asignaciones: <=  (non-blocking)
💡 Si falta una señal en la lista de sensibilidad de un bloque combinacional → se infiere un latch (comportamiento incorrecto en síntesis). Si no asignas valor en todos los caminos de un if → también latch.
Reset síncrono vs asíncrono
// ASÍNCRONO — reset en la lista de sensibilidad
always @(posedge clk or negedge rst_n)
  if (!rst_n) Q <= 0; else Q <= D;

// SÍNCRONO — solo el reloj en la lista
always @(posedge clk)
  if (!rst_n) Q <= 0; else Q <= D;

🏗️ Jerarquía, parámetros e instanciación EXAMEN

✓ Un módulo puede instanciarse tantas veces como haga falta, con o sin parámetros. No hace falta que sea parametrizable para instanciarlo múltiples veces.
// Instanciación por ORDEN (posición)
mux u0(in0, in1, sel, y0);

// Instanciación por NOMBRE (más seguro)
mux u1(.y(out), .a(y0), .b(in1), .sl(sel));

// Con parámetros
sumador #(16) sum16(.a(a), .b(b), ...);
sumador #(.n(4)) sum4(.a(a), .b(b), ...);
Parámetros
module contador(clk, Q);
  parameter M = 16;          // módulo
  parameter N = $clog2(M);   // bits necesarios
  output reg [N-1:0] Q;
💡 $clog2(M) devuelve el techo de log₂(M). Para M=16 → N=4. Para M=10 → N=4.

💾 Memorias en Verilog EXAMEN

Dimensionamiento — trampa clásica

Para imagen de 50×25 píxeles con direccionamiento X-Y:

  • X va de 0 a 49 → necesita 6 bits (2⁶=64 valores, cubre hasta 63)
  • Y va de 0 a 24 → necesita 5 bits (2⁵=32 valores, cubre hasta 31)
  • Dirección máxima = 64×32 − 1 = 2047, así que la más alta es 2047
💡 No es 50×25=1250. Las memorias tienen potencias de 2. Siempre redondeas al siguiente 2ⁿ en cada dimensión.
Declaración
// Memoria de 1024 palabras de 8 bits
reg [7:0] mem [0:1023];

// Acceso
dato = mem[direccion];
mem[addr] = dato_entrada;
ROM vs RAM
  • ROM: solo lectura. Tiene ADDRESS y Q (salida). Reloj para sincronizar lecturas.
  • RAM: lectura y escritura. Añade DATA (entrada) y WREN (habilitación escritura).
  • RAM doble puerto: dos interfaces A y B para el mismo conjunto de datos.

🔬 Estructura del Testbench EXAMEN

// Un testbench NO tiene entradas ni salidas
`timescale 1ns / 100ps
module tb_DFF();          // sin puertos

  // Entradas DUV → reg (damos valor en initial)
  reg CLK, D, RST;
  // Salidas DUV → wire
  wire Q, Qb;

  // Instanciar DUV
  DFF_hl DUV(.clk(CLK),.d(D),.clear(RST),.q(Q),.qb(Qb));

  // Generador de reloj
  always #5 CLK = ~CLK;

  // Casos de test
  initial begin
    CLK = 0; RST = 0; #20;
    RST = 1; D = 1;   #20;
    D = 0;            #20;
  end
endmodule

⏰ Cuándo cambiar señales & aserciones EXAMEN

⚠️ NUNCA cambiar entradas del DUV en el flanco activo de reloj. Se producen condiciones de carrera (race condition).
✓ Cambiar entradas en el flanco inactivo (negedge si el diseño es posedge). Así las señales están estables cuando llega el flanco activo.
// Correcto: cambiar en negedge para DUV posedge
task DATA;
  input d_bit;
  begin
    @(negedge CLK);   // espera flanco INACTIVO
    D = d_bit;
  end
endtask

// Reset: desactivar en negedge también
task RESET;
  RST = 0;
  repeat(2) @(negedge CLK);
  RST = 1;
endtask
Aserciones EXAMEN

Son mecanismos autónomos de verificación insertados en el código RTL. No son tasks externas en el testbench; son módulos que se instancian condicionalmente.

// Aserción: detecta cuando más de un master toma el bus
`ifdef VERIFICACION
  ASER_UNIMASTER #(masters) VERIF_1(GNT_n);
`endif
  • Se activan automáticamente al cambiar la señal monitoreada
  • Imprimen mensajes de error y detienen la simulación ($stop)
  • Pueden incluirse/excluirse con directivas de compilación (`ifdef)

⚖️ FPGA vs ASIC vs PLD EXAMEN

ASICFPGAPLD

💡 Regla rápida: FPGA → más barato, más rápido diseñar, más fácil modificar. ASIC → mejor rendimiento final pero coste y tiempo de desarrollo altísimos. Las FPGAs también se usan como prototipado de ASIC.
⚠️ Trampa: El ASIC es más caro de diseñar que una FPGA, pero si produces millones de unidades, el coste por unidad puede ser menor. El examen pregunta sobre coste de diseño/desarrollo, no de producción en masa.

🏛️ Arquitectura interna de una FPGA EXAMEN

Bloques fundamentales (3 elementos básicos)
🧠 Bloques Lógicos Prog. 🔗 Interconexión Prog. 📡 Bloques E/S
Célula lógica (LE / LC)
  • LUT (Look-Up Table): tabla de verdad programable de n entradas. Implementa cualquier función combinacional.
  • Flip-flop: registro asociado a la LUT
  • Métrica: nº de LEs equivalentes (LUT-4 + FF asociados)

  • Multiplicadores y sumadores dedicados (DSP blocks)

  • Transceptores Gigabit para comunicaciones serie de alta velocidad
Tensiones de alimentación EXAMEN
✓ CORRECTO: El núcleo y los bloques I/O pueden alimentarse a tensiones distintas. Además, pueden existir diferentes tensiones para distintos bancos de I/O.

El núcleo tiene tendencia a bajar tensión con cada generación tecnológica (3.3V → 2.5V → 1.8V → 1.2V → ~1.0V actual).

📡 Verificación física: SignalTap EXAMEN

SignalTap es el analizador lógico embebido de Quartus. Captura señales internas de la FPGA en tiempo real.

Consumo de memoria = nº señales × profundidad de captura
  • Para reducir memoria necesaria: reducir el tiempo de adquisición (= número de muestras / profundidad)
  • Reducir el periodo de muestreo no reduce la memoria; de hecho requiere más muestras para el mismo tiempo
  • Cambiar a modo post-disparo no reduce memoria; solo cambia qué parte se guarda
💡 Cuando en FPGA no asignas pin a una E/S → Quartus le asigna automáticamente un pin libre. No falla la programación.

🎯 Respuestas tipo para el test — patrones recurrentes en exámenes

Preguntas sobre Verilog RTL
  • Secuencial → always @(posedge clk) + non-blocking <=
  • Combinacional → always @(*) + blocking =
  • Instanciación → siempre posible, con o sin parámetros, tantas veces como quieras
  • Asignación a wire dentro de always → error
  • Salida de submódulo → debe conectarse a wire
  • Proceso initial → NO sintetizable, solo testbench
  • Procesos en paralelo, sentencias internas secuenciales
Preguntas sobre simulación
  • Non-blocking encadenados → shift register predecible
  • Blocking encadenados en secuencial → resultado impredecible
  • Señales internas en ModelSim → sí, pero hay que relanzar
  • Cuándo cambiar entradas → en el flanco INACTIVO
Preguntas sobre FPGAs
  • OTP → solo antifusible
  • Volátil → solo SRAM
  • Más usada actualmente → SRAM
  • FPGA vs ASIC: FPGA más barato/rápido de diseñar; ASIC mejor rendimiento
  • Tensión E/S → puede variar por banco, diferente al núcleo
  • Elementos básicos FPGA → LB + interconexión + E/S (no incluye memoria ni PLL como "básicos")
Preguntas sobre verificación
  • Aserción → mecanismo autónomo insertado en el RTL, no una task del testbench
  • DUV → Device Under Verification
  • Reducir memoria SignalTap → reducir tiempo de adquisición
  • Reset asíncrono en testbench → desactivar en flanco inactivo

🧠 Método para ejercicios: cómo trazar código Verilog paso a paso

Ejercicio tipo: cronograma de simulación
  1. Identifica todos los procesos (initial, always) → se ejecutan en paralelo
  2. Dentro de cada proceso, las sentencias son secuenciales
  3. Para non-blocking: anota qué se lee (valor antiguo) y qué se escribirá después
  4. Para blocking: aplica el cambio inmediatamente
  5. Los retardos #N en begin/end son acumulativos; en fork/join son relativos al inicio del bloque
  6. Dibuja un eje temporal y marca cada evento
Ejercicio tipo: ¿cuántos FFs infiere este código?
  1. Cada reg asignado con <= dentro de un always @(posedge clk) → 1 FF por bit
  2. Un reg [3:0] → 4 FFs
  3. Si el reg está en un combinacional (always @(*)) → 0 FFs
  4. Asignaciones continuas (assign) → 0 FFs (lógica combinacional)
💡 Ejemplo del examen: registro 4 bits con reset → 4 FFs. Si por error metes la salida TC dentro del always secuencial → 5 FFs (1 FF de más, llega tarde y sin reset).
